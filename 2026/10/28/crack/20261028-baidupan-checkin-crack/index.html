逆向百度网盘签到自动化

发表于 2026-10-28

网上流传的百度网盘签到脚本几乎都用的同一套接口，拿来实测直接报 400。排查发现这批接口已经被百度下线了一年左右，现行可用的参数组合完全不同。本文记录从排查到复现的完整过程，以及防封号的请求编排设计。

背景

百度网盘会员有一套成长值体系，每天可以白嫖两笔成长值：

  • 签到：每日签到领成长值（连续签到有递增奖励）
  • 答题：每日一题，接口直接返回答案，提交就给分

排查过程

先排除 cookie 问题

第一步是分清”cookie 失效”还是”接口变了”。拿同一个 cookie 打两个不同端点：

端点 参数 结果
/rest/2.0/membership/user?method=query web=5 200，返回真实会员数据（等级 9、成长值 69925、年度 SVIP）
/rest/2.0/membership/level?method=query web=5 400 + 100002 Param error
/rest/2.0/membership/level?method=signin web=5 400 + 100002 Param error

结论很清晰：cookie 是好的（user 接口正常吐数据），是 membership/level 这个端点的参数契约变了。再换成无 cookie 请求 level 端点，同样 400——它压根没走到鉴权那步，参数校验就拒了。

换 web=1、POST、加 clienttype=0 等参数变体全部无效，这条老路彻底死了。

GitHub 考古

去翻还在维护的签到项目，Sitoi/dailycheckin 的 issue #534（2025-10）就在报”百度网盘签到无反应”，至今没修——全量代码搜索发现几十个项目还在抄这套死掉的接口。

唯一有价值的是 xvkong233/qlscript 的 baidu_netdisk.py：作者在 2026-10 用 App 13.34.3 真机抓包重做了整套实现，注释里连反欺诈指纹、风控错误码表都写全了。从中拿到关键结论：

老接口 web=5 被服务端下线，现行可用的是 web=1&clienttype=5&clientinfo=wap（wap 网页端通道）。

关键细节

cookie 放会话 jar，不要写死 Cookie 头

把 cookie 字符串塞进 requests.Session().cookies（domain 填 .baidu.com），而不是拼到请求头里。原因：请求过程中服务端会下发 BAIDUID、PANWEB 等 Set-Cookie，会话 jar 会自动带上后续请求，写死 Cookie 头这些就全丢了，会话上下文不完整，风控侧看起来就是异常客户端。

cookie 要求很低：成长值/答题/信息查询这条链路只要 BDUSS 一个字段就够（实测无 STOKEN 全通）。整串浏览器 cookie 复制进来也行。

判定位汇总

场景 判定
签到状态 data.today_signed
签到成功 error_code == 0，积分在 result.points
重复签到 error_code == 421001 或 error_msg 含 repeat/已签
cookie 失效 error_code == -6 或 error_msg 含”登录”
取题成功 errno == 0，答案在 data.answer/data.ask_id
已答过 data.answer_status == 1（取题时）或 errno == 9502（提交时）
答题成功 响应含 data.score

防封号设计

签到类自动化最大的风险不是接口，是请求行为把自己送进风控。这套实现的约束：

  1. 先查后写：signinlist 是只读查询，先看 today_signed，已签就绝不再发 signin 写请求。写请求每天最多出现一次
  2. 幂等短路：答题先看 answer_status，已答过不发提交请求；服务端兜底的 421001/9502 也按”已签/已答”归为幂等成功，不重试
  3. 请求量恒定：每天全流程 35 个请求（3 只读 + 最多 2 写），间隔 23 秒，不并发、不重试轰炸
  4. 浏览器同源：UA/Referer 对齐 wap 成长值任务页，cookie 走会话 jar 保持会话连续性

即便脚本一天跑多次，重复执行时全部走只读路径，行为等价于多刷新了几次页面。

边界：没做的事

百度任务体系还有几条通道，逆向结论记录在这里但没有自动化：

  • 任务中心签到（/coins/taskcenter/signin，金币/任务系统 H5）：必须带 z/channel/offlinepackage 等完整客户端参数，其中 z 是 sofire 反欺诈指纹（com.baidu.sofire.ac.FH.gz），由设备+登录态在本机算出，不能跨账号/跨设备复放，拿别人的抓包值只会收到 errno=2。要自动化这条通道得上 Frida 在真机现场取指纹，成本完全不成比例
  • PC 积分签到（/coins/pc/signin）：需要伪装 PC 客户端 Electron UA，奖励是金币不是成长值
  • 补签（/coins/taskcenter/suppsignin）：与任务中心共用设备链和 z 指纹，同上不碰

成长值签到+答题这条 BDUSS 就能走的通道，是整套体系里唯一不需要对抗设备指纹的，性价比最高。
